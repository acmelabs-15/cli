Every outside program that a command runs now has a time limit and an output limit: 5 minutes, and 10 MB on stdout and on stderr each, unless the command sets others for that call. At a limit, or when the user cancels, acmelabs stops the program and every program it started, so a hung program, a flood of output, or a child it left behind no longer keeps the command waiting or fills memory. A limit ends the command with exit 3 and a message that names the program and the limit, such as `gh api ... ran longer than 5 minutes and was stopped` or `gh api ... printed more than 10 MB on stdout and was stopped`. A program still gets the whole environment, plus any variables the command adds for that call. git is the one exception: acmelabs runs git without the `GIT_` variables of its environment, so neither a git hook's `GIT_DIR` nor a setting such as `GIT_SSL_CAINFO` reaches acmelabs's git calls.

Every request that a command sends has limits too: 1 minute to get its whole answer, body included, and 10 MB of body, unless the command sets others for that call. A body whose `Content-Length` is past the limit is never read. A limit ends the command with exit 3 and a message that names the method, the URL and the limit, such as `GET https://registry.npmjs.org/@acmelabs%2fcli got no whole answer within 1 minute and was stopped` or `... got a body of more than 10 MB and was stopped`. A request that fails in the network, such as a refused connection or a failed TLS handshake, now ends the command with exit 3 as well, not as a bug in acmelabs, with a message that names the method, the URL and what failed. A cancel stays a cancel.
